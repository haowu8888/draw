# Draw — project context

Clone of the draw.taoya.art whiteboard SaaS. See README.md for features, layout and the open API.

- Entry points: `server/index.ts` (Hono HTTP + `/api/collab` WebSocket upgrade), `src/main.tsx` (routes).
- Data: SQLite at `$DATA_DIR/draw.db` (default `data/`). App tables are created in `server/db.ts`; better-auth tables are migrated at startup in `server/auth.ts`.
- Scene sync: clients send changed Excalidraw elements over the WebSocket; `server/boards.ts` merges by `version`/`versionNonce`, caches pages in memory and flushes to SQLite (~800 ms). Board-level events go through `boardEvents` → `collab.ts` broadcast.
- Custom canvas nodes: markdown / codeblock / chart / link are plain `rectangle`s with `customData.kind`, drawn as HTML overlays (`node-overlays.tsx`) mounted between Excalidraw's static and interactive canvases; elements stacked above a node are re-drawn as SVG inside its overlay, and exports snapshot overlays to images (`withNodeSnapshots`, modern-screenshot). Code display (`kind: "code"`) and video stay `embeddable`s with link `https://draw.local/node/<kind>`. Legacy embeddable versions are converted on load (`migrateNode`). Content renderers live in `src/board/nodes.tsx`.
- Editor UI mirrors the original's board editor: `ops.ts` (selection ops, palette/fill-mode color scheme, Excalidraw action bridge), `selection-bar.tsx` (bottom properties bar), `diagram.ts` + `diagram-panel.tsx` (Mermaid diagrams as grouped elements with `customData.diagram`, dark side code panel with live preview), `shapes.tsx` (shape library as native shapes or closed `line`s with `customData.shape`, device outlines), `quick-connect.tsx`, `context-menu.tsx`, `frames.tsx` (outlines, navigation, status pills), `export-dialog.tsx`, `node-panels.tsx` (Markdown / code-display side panels on `code-editor.tsx`, a CodeMirror wrapper), `chart-panel.tsx` (chart bar controls + floating data table), `node-bars.tsx` (code block / link card ↔ web embed / code-display size bars), `codeblock.tsx` (highlight.js highlighting + auto-detect, content-sized boxes, in-place editor), `upload-progress.tsx` (per-file uploads with progress), `locked-hint.tsx`.
- `automation.ts` exposes `window.draw` in the editor (info / elements / add / update / move / remove / select / fit / undo / redo / exportPng / exportCover; `window.draw.help()` prints the reference). Each mutating call is one undo step. Side-panel edits preview without history and commit once on close (`updateNodeData`); rollbacks go through `rollbackScene` so versions stay monotonic for collaborators. Canvas font id 2 ("Helvetica") is served as Inter (`fonts.ts`).
- Code-display nodes run user code only inside `sandbox="allow-scripts"` iframes (`src/board/sandbox.ts`); never render user code/markdown HTML in the app origin.
- Dev: `npm run dev` (vite 5173 proxies `/api`, `/uploads` and WebSocket to 3000). `NODE_ENV` must be `development` for dev (scripts set it).
- `better-sqlite3` is pinned to 12.11.1: 13.x ships no Windows prebuilt binaries, and building from source needs Visual Studio.
- Scripts use `cross-env`; the server loads `.env` via `--env-file-if-exists`.
- `scripts/patch-excalidraw.mjs` (postinstall) patches the installed Excalidraw so embeddables do not get a link icon, matching the original; re-check it when upgrading Excalidraw. After reinstalling, clear `node_modules/.vite` (or run vite with `--force`) so the dev pre-bundle picks it up.
